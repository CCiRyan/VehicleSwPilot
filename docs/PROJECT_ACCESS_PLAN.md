# 待确认：多项目与角色授权实施范围

以下为下一步后端实施方案。当前尚未启用，现有令牌和数据库没有变更。

## 数据与旧项目

- 现有 VCP 空间及其历史 BMS 工件继续使用原 `backend/data/pilot.sqlite` 和检查点；不搬移、删除或重新批准历史工件。
- 新项目采用服务端生成的 UUID，独立保存工件/版本、知识库/Faiss、Agent 配置与运行、检查点、追溯、审计和目录设置。
- 所有项目数据接口使用请求上下文选择资源，禁止通过改写全局 Store 切换，防止并发混用。
- 项目 ID 不能授予访问权。每次请求先校验有效令牌，再校验创建者或成员资格；无权访问时不透露项目是否存在。

## 身份、成员与轮换

- 沿用本地部署的令牌账号模式。只持久化令牌的 SHA-256 指纹作为身份，不保存、返回或记录原始令牌。
- 新项目初始只对创建者可见。只有创建者可以授予已配置角色账号的成员资格；安全经理也不会自动看到他人的新项目。
- 角色成员资格不能提升角色本身的权限。配置管理员不能借成员身份批准工件，审核员不能修改代码。
- 现有默认空间保留原角色访问规则。新增角色按下表访问默认空间；各角色使用独立令牌。
- 轮换令牌时须显式迁移成员/项目归属，不能仅凭项目 ID 接管；未来企业部署应替换为用户账号/OIDC。

## 角色权限

|角色|写入与操作范围|
|---|---|
|软件工程师|已有软件需求、架构、详细设计、编码阶段权限；不批准工件|
|系统工程师|沿用已有阶段与评审权限|
|评审负责人|评审全部阶段、通过/驳回、记录意见；不编辑工程工件|
|配置管理员|Agent 阶段提示词、知识库与目录配置、冻结已批准工件基线；不批准工件，不编辑固定调度/安全/执行节点|
|ASPICE 审核员|读取项目证据、创建和跟踪审核发现、记录整改证据及关闭意见、导出报告；不编辑工件或配置|
|安全经理/测试工程师|保留现有操作范围；新项目仍要求成员资格|

`PILOT_REVIEW_TOKEN`、`PILOT_CONFIG_TOKEN`、`PILOT_ASPICE_TOKEN` 将添加到配置模板；如生成本地令牌，仅写入被 Git 忽略的 `.env`，不会在日志、接口或聊天中显示。

## 配置和审核记录

- 受控基线只接受当前已批准版本，保存不可变的内容、来源、追溯和哈希快照；后续修改显示差异，不覆盖快照。
- 审核发现记录负责人、状态、证据引用、意见和版本，并写入审计日志；不据此宣称正式 ASPICE 能力评级。
- 权限、跨项目读取/写入、并发隔离、重启持久化和越权路径均必须通过测试后启用。

## 当前已完成的独立工作

- 项目定义表单：用户填写真实项目事实，生成待人工评审系统需求输入；待确认信息不由 AI 假定。
- Agent 任务 ASIL 显式选择；定义中的未确认等级不自动转换成 ASIL B。
- 显式扫描/导入/导出配置目录：当前只访问本工程内路径、禁止链接/越界、保护内部目录、拒绝覆盖现有文件；来源和导出哈希可追溯。
- Docker 执行入口及 `scripts/execution_smoke.py`。本机没有 Docker，真实编译与测试尚未执行，需准备运行环境后验收。
